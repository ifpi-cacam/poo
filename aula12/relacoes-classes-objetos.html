Como ler os exemplos

Referência não é cópia

Um atributo de tipo classe guarda uma referência para uma instância. Na agregação, o objeto relacionado é criado externamente e passado ao construtor. Na composição, o objeto que contém a referência instancia a parte. Essas relações descrevem o design; Java não apaga automaticamente objetos referenciados quando o todo deixa de ser usado.

Agregação

A instância pode existir antes e ser compartilhada por objetos diferentes.

Composição

A criação interna expressa propriedade, embora setters possam permitir trocar a referência depois.

src/exemplo/agregacao

Curso mantém referência para Sala

Curso declara Sala sala. O construtor recebe uma Sala existente e atribui a this.sala. O Main cria uma única s1 e passa a mesma referência ao construir c1 (POO, 20) e c2 (Redes de Computadores, 30). Assim, dois cursos compartilham uma sala; os cursos não criam a Sala.

classDiagram
 class Curso { -String nome; -int duracao; -Sala sala; +Curso(String,int,Sala) }
 class Sala { -String nomeSala; -String localSala; +Sala(String,String) }
 Curso "0..*" o-- "1" Sala : sala recebida
Instâncias do Main: uma Sala e dois Cursos. Não existe coleção de cursos armazenada em Sala.
flowchart LR
 s1["s1 : Sala
Sala de Artes · Dep-01"]
 c1["c1 : Curso
POO · 20"] -->|sala| s1
 c2["c2 : Curso
Redes de Computadores · 30"] -->|sala| s1
Ordem real: new Sala(...), depois new Curso(..., s1) duas vezes.

src/exemplo/composicao

Cliente cria sua Conta

O campo Cliente.conta recebe uma nova instância criada dentro do construtor: this.conta = new Conta(saldo). Cada Cliente criado ganha sua própria Conta. O setter setConta permite substituir essa referência posteriormente. Conta declara somente saldo e seu construtor.

classDiagram
 class Cliente { -String nome; -int idade; -Conta conta; +Cliente(String,int,double); +setConta(Conta) void }
 class Conta { -double saldo; +Conta(double) }
 Cliente "1" *-- "1" Conta : criada pelo construtor
flowchart LR
 c1["c1 : Cliente
Maria Silva · 22"] -->|conta| ct1["Conta · saldo 200"]
 c2["c2 : Cliente
Pedro Jose · 30"] -->|conta| ct2["Conta · saldo 150"]
O arquivo composicao/Main.java tem essas inicializações no corpo da classe como campos de instância e não declara um método main. Portanto, não é um ponto de entrada executável; as instâncias surgem ao instanciar Main.

src/exemplo/escola

Aluno compõe Registro; Registro agrega Data

O construtor de Aluno cria um novo RegistroAcademico com a média e a data recebidas. Cada Aluno tem seu próprio Registro. O construtor de Registro recebe e armazena uma instância Data. O Main cria uma única dt1 (22/10/2025) e a passa aos dois Alunos. Logo, os dois registros apontam para a mesma Data.

classDiagram
 class Aluno { -String nome; -int idade; -RegistroAcademico ra; +Aluno(String,int,Data,double) }
 class RegistroAcademico { -double mediaGeral; -Data dtInicio; +RegistroAcademico(double,Data) }
 class Data { -int dia; -int mes; -int ano; +Data(int,int,int) }
 Aluno "1" *-- "1" RegistroAcademico : ra criada no construtor
 RegistroAcademico "0..*" o-- "1" Data : dtInicio recebida
O exemplo concreto cria dois Alunos, dois Registros e uma Data compartilhada.
flowchart LR
 dt["dt1 : Data
22/10/2025"]
 a1["al1 : Aluno · média 7.5"] -->|ra| r1["RegistroAcademico"] -->|dtInicio| dt
 a2["al2 : Aluno · média 4.5"] -->|ra| r2["RegistroAcademico"] -->|dtInicio| dt
mostraData() percorre Aluno → RegistroAcademico → Data. Alterações à instância Data compartilhada podem ser vistas pelos dois registros.

Compra, Cliente, Produto e Data

TesteAgregacao cria as datas, o Produto e o Cliente primeiro, e passa referências ao construtor de Compra. Compra calcula o total uma vez durante a construção; alterações posteriores não o recalculam automaticamente.

Pedido e ItemProduto

O construtor de Pedido cria ItemProduto e calcula o valor. A classe tem setItem, portanto a referência pode ser substituída depois da construção.

Precisão do modelo

Limites que o código deixa claros

Setters alteram vínculos

setSala, setConta, setRa, setDtInicio e setItem podem substituir referências.

Multiplicidade não é validação

O desenho resume os objetos observados e campos. O código não controla cardinalidades, mantém coleções reversas nem impõe regras de ciclo de vida.
